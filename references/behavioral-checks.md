# 교정 행동 점검 사례

스킬 수정 후 실제 교정을 평가할 때 사용하는 입력과 보존 기준입니다. 특정 문구와 일치하는지를 점수화하지 않습니다. 교정 전 원문과 결과를 대조해 사실·조건·추정·접속 관계가 유지되는지 확인합니다. 아래 기준은 모델 성능 수치나 자동 합격 판정이 아닙니다.

| 입력 | 기대하는 행동·보존 기준 |
|---|---|
| 이 계획이 성공할 가능성은 아직 확인하지 않았다. 실패할 수 있으므로 성공을 전제하지 않는다. | 가능성이 미확인이라는 상태와 실패 가능성·인과를 보존. 대안 모델이나 추가 준비 절차를 넣지 않음. |
| 조기 종료·재샘플링의 오판 비용을 기록한다. 비용은 추가 GPU 시간으로 정의한다. | 비용의 정의를 그대로 유지하고 압축 명사구만 풀기. 이미 제공된 비용 정의를 다시 묻지 않음. |
| 계획 수정과 단순 검증 선택의 효과를 절제한다. | 의미 확인 전 원문 유지. 효과·선택의 뜻에 필요한 확인만 본문 밖에 적기. |
| 모델을 실행하기 전에 무엇을 고정하고 어떤 비용을 셀지 정한다. | 실행 전이라는 순서, 고정 항목과 비용 결정이라는 두 내용을 보존. 의무·실험 지표를 추가하지 않음. |
| 연구 부재를 단정하지 않고 비교 조건과 반증 가능한 질문으로 적는다. | 연구가 없다는 단정을 피한다는 의미를 보존. ‘선행’ 범위나 대상·실험 절차를 지어내지 않음. 호응을 확정할 수 없으면 확인. |
| API를 통해 자료를 전달한다. 모델의 표현 공간은 3차원 좌표계로 시각화한다. 처리 시간이 18시간에서 11시간으로 줄었을 수 있다. | API 경로·수학적 좌표계·수치·가능성을 유지. 문서 종류 미지정 시 원래 어미 유지. |
| 사람은 하나지만 자리는 두 개입니다. | 자리의 뜻을 임의로 좌석·역할·정원으로 단정하지 않음. 뜻 확인 전 원문 유지. 대비 관계를 단순 나열로 바꾸지 않음. |
| 실제 양식의 6칸을 채운다. 장치의 손잡이를 돌린다. | 문자 그대로의 표현 유지. 변수·항목·파라미터로 바꾸지 않음. |
| 백본 공유가 표현 공유를 보장하지 않는다. | 보장할 수 없다는 뜻을 실제로 공유하지 않는다는 사실 단정으로 바꾸지 않음. |
| CE 사용 여부로 이산·연속을 판정하지 않는다. | ‘만으로’를 임의로 추가해 원문의 기준 배제를 완화하지 않음. |

이 검토에서는 원문 의미에 영향을 주지 않는 자연스러운 지시어·조사·어휘 변경을 허용합니다. 한 글자도 바꾸지 않는 검사가 아닙니다. 확인 질문은 교정에 필요한 의미가 불분명할 때만 적고, 실험 설계·사실 검증으로 범위를 확장하지 않습니다.

검사기의 CLI 회귀 테스트(`tests/test_scan_slop.py`)는 후보 탐지·미탐·오탐과 입력 파일 불변성만 확인합니다. 위 의미 보존 행동을 자동으로 검증하지는 않습니다.

가운뎃점은 목록의 병렬·대안·공동 조건 중 무엇인지 문맥에서 판단합니다. 조기 종료·재샘플링의 오판이 의사결정 오류인지 과정 중 오류인지 불분명하면 그 범위를 좁히지 않습니다.

## 강의·실습 자료 추가 점검

| 입력·문맥 | 기대하는 행동 |
|---|---|
| 손이 없어서 못 한 겁니다. 주어는 챗봇. | 기능·접근 대상·실행 조건 중 무엇을 뜻하는지 원문에서 확인. 권한이 없었다고 추측하지 않음. 비유를 문자 그대로 이해하거나 모든 챗봇의 능력으로 일반화하지 않음. |
| 앱 안의 다른 자리 / 1층에서 부탁 / 3층으로 옮겨 폴더 지정 | 원문에 있는 기능명·화면명과 대응시켜 설명. 앞 차시에 정의했을 가능성을 고려하고 물리적 층수·실제 좌석·전문 계층 용어와 구분. |
| 같은 프롬프트가 대화 시연과 실행 시연에 반복됨 | 입력 동일성이 비교 조건이면 글자까지 보존. 반복 문구라는 이유로 삭제·윤문하지 않음. |
| 같은 요청 뒤 파일 이름이 바뀌고 ‘바뀐 건 자리’라고 결론 | 요청·실행 경로·폴더 지정 등 관찰된 조건을 구분. 단일 원인이나 제품 전체의 능력을 새로 단정하지 않음. |
| 되돌려 보지 않았다면 아직 성공이 아닙니다. 완료 조건으로 제시됨 | ‘되돌리기 확인 전에는 미완료’라는 조건 보존. 선택적인 권고로 약화하거나 원문에 없는 안전·성공 조건 추가 금지. |
| 복사본으로 작업합니다. / 이런 폴더, 있으시죠 / 직접 해보겠습니다 | 실제 절차, 학생에게 하는 질문, 강사의 시연 예고라는 역할이 분명하면 유지. 구어체나 짧은 어미 자체를 슬롭으로 판정하지 않음. |

검토자가 제공받지 못한 앞선 차시·제품의 현재 기능·실제 권한 설정은 확인한 것처럼 쓰지 않습니다. 스킬 개선만 요청받았으면 입력 자료에 쓰지 않고 원문에서 추출한 판단 기준만 개선합니다.

## 논문·기술 해설 추가 점검

| 입력·문맥 | 기대하는 행동 |
|---|---|
| 호라이즌 3형제: T_o, T_p, T_a | 친족 은유를 평이한 제목으로 바꾸되 세 항목·기호·관측/예측/실행 구분 유지. |
| 액션을 예측하지 말고 정제하십시오. 본문은 노이즈 예측과 액션 시퀀스 예측을 설명함 | 예측·정제가 어느 수준의 차이인지 확인. 지시형 어미만 바꿔 해결한 것으로 보고하지 않음. |
| 한 가지 변경으로 동시에 해결한다. 본문에는 여러 추가 설계·조건을 제시함 | 같은 문서 안에서 주장 범위 대조. 잘못됐다고 확정하거나 근거 없이 ‘도움이 될 수 있다’로 약화하지 않음. |
| 조건 아래 일대일 대응이 증명됨 / 실험에서는 특정 범위만 관찰됨 | 증명·관찰·해설을 구분하고 실제 근거에 맞는 주장 강도 유지. 강한 표현 자체를 금지하지 않음. |
| rollout 간 다봉, 같은 rollout 안에서는 한 모드에 커밋 | 두 범위와 시간적 일관성 구분 보존. 정책 전체가 한 모드만 생성한다고 바꾸지 않음. |
| 로봇이 손잡이를 3회 이상 돌립니다. | 실제 조작 대상·행동·최소 횟수 유지. 비유적 손잡이 규칙으로 교정 금지. |
| 본문은 추론 10회, 부록은 16회라고 원문이 차이를 설명함 | 두 수치와 출처 구분 유지. 임의 평균·통일 금지. |
| 슬라이더 안내에는 ‘논문이 보장’, 본문에는 실험 결과를 제시함 | 안내 문자열도 검토하고 근거 종류가 바뀌었는지 확인. 코드를 실행하거나 원 논문을 검증했다고 주장하지 않음. |

수식·그림 번호·보고 수치와 기술적 주장 자체를 수정하는 일은 문체 분석과 구분합니다. 읽기 전용 자료의 문장 예시는 스킬 개선에만 사용하고 원본에 적용하지 않습니다.

## 병목 진단 추가 점검

- 여러 원인을 문단마다 `X가 병목입니다`로 제시하면 실제 제한 대상·근거를 확인합니다. 설명 없이 진단만 반복하는지 봅니다.
- `정책 표현이 병목입니다`의 의미가 ‘정책 표현 방식이 성능을 제한한다’로 본문에서 확인되면 그 관계를 직접 설명할 수 있습니다. 수집 지연·학습 속도 같은 새 원인을 넣지 않습니다.
- 정확한 bottleneck 용법, 제목과 결론에서 같은 논지를 재확인하는 반복은 자동으로 슬롭 처리하지 않습니다. 문체 점검을 이유로 실제 성능 제한이라는 주장 강도를 낮추지 않습니다.

## 상호영향·함께 보기 문단 추가 점검

- `다섯 축은 따로 놀지 않는다 → 두 영향 사례 → 다섯 축을 ‘함께’ 본다`는 개별 단어보다 문단의 반복 구조를 검토합니다. `유기적으로 연결된다` 같은 다른 상투어로만 교체하지 않습니다.
- 제시된 관계·주장 강도·다섯이라는 수를 보존합니다. 이름이 없는 두 항목이나 구체적인 측정·관리 절차를 추가하지 않습니다.
- 실제 좌표축·회전축·정의된 분석 차원, 실제로 설명된 상호작용과 공동 검토는 유지할 수 있습니다. `함께`나 `축`의 등장만으로 판정하지 않습니다.

| 예시·문맥 | 기대하는 행동 |
|---|---|
| 마케팅은 단순히 서비스를 알리는 일이 아니라 고객의 마음을 이해하는 일입니다. | 수사용 대조인지 실제 배제 주장인지 구분. 부정·한정을 삭제하거나 새로운 마케팅 이론을 보충하지 않음. |
| 브랜드의 방향성과 고객 반응을 함께 봅니다. | 공동 검토의 목적을 문맥에서 찾음. ‘비교한다’, ‘평가한다’, ‘개선한다’ 중 하나로 임의 확정하지 않음. |
| 정서의 결 / 여운의 농도 / 맥락의 밀도 | 실제 대상·방법이 있으면 직접 설명. 브랜드 회상률·전환율 같은 지표를 추가하지 않음. 물리적 결·농도·밀도는 유지. |
| 그 기준에 따라 선정 / 이를 통해 신뢰도 향상 | 앞뒤 문장·표·도식에서 지칭 대상을 확인. 없는 선행 문장을 있다고 만들거나 새 선정 기준·인과를 창작하지 않음. |
| 판단 기준 / 작동 구조 / 운영 관점이 반복됨 | 실제 정의·대상 없이 틀만 채우는지 확인. 같은 개념의 용어 반복은 보존하고 동의어로 돌려 쓰지 않음. |
| 중요한 것은 인식 변화 / 기준은 분명합니다 | 예고 문구와 실제 정보를 구분. 중요성이라는 주장과 실제 기준을 삭제하지 않음. |
| 정보 전달보다 브랜드의 태도를 보여주는 데 가깝습니다. | 근접성·비교의 정도를 보존. ‘브랜드 태도를 보여주는 것이다’나 ‘그것이 더 중요하다’로 단정하지 않음. |
| 판단 기준, 운영 방식, 핵심 메시지의 세 항목 | 각 항목의 독립성·추상화 수준을 확인. 세 항목을 임의로 둘·넷으로 바꾸거나 3항 나열을 순차적 3단계로 바꾸지 않음. |

8유형 전체에 대한 문맥 점검 기준입니다. CLI 테스트가 이를 모두 자동 평가한 것으로 소개하지 않습니다. 사용자 예시는 편집 선호의 근거이며 언어학적 표준 분류나 AI 작성자 판별 성능의 근거가 아닙니다.

## 1.1.0 전체 점검에서 추가한 기준

문맥이 충분한 경우에는 실제 교정도 이루어지는지 확인합니다. 의미가 불명확한 구간 하나 때문에 나머지 교정까지 멈추지 않습니다.

| 입력·문맥 | 기대하는 행동 |
|---|---|
| 한 사람이 기획과 검수 두 역할을 맡습니다. 사람은 하나지만 자리는 두 개입니다. | 앞 문장이 같은 내용을 이미 밝히므로 경구형 반복을 줄일 수 있음. 담당자 수와 두 역할은 보존. |
| 기준은 분명합니다. 금요일 17시까지 제출한 안건만 심사합니다. | 정보 없는 예고를 줄이되 시각·대상·‘만’의 범위 유지. |
| 여운의 농도를 높입니다. 마지막 대사를 줄이고 엔딩 뒤 침묵을 3초 늘립니다. 분량은 40초입니다. | 대상과 증가 의미를 살려 표현을 다듬을 수 있음. 문장이 인접했다는 이유만으로 대사·침묵 조정을 여운의 원인이나 수단으로 새로 연결하지 않음. 수치 유지. |
| 브랜드의 방향성과 고객 반응을 함께 봅니다. 광고의 약속과 후기의 경험이 일치하는지 확인합니다. | 광고·후기가 전체 방향성과 고객 반응을 모두 정의한다고 단정하지 않음. 두 문장을 합칠 때 넓은 대상을 특정 예시로 축소하지 않음. |
| 이 대화의 파일 실행 기능은 비활성화되어 있습니다. 손이 없다는 뜻입니다. 사용자가 복사본을 만들어야 합니다. | 비유로 반복한 부분은 줄이되 기능 상태·의무 유지. 비활성화의 원인이나 권한 상태를 추측하지 않음. |
| 판정 기준은 오차 0.1 이하입니다. | 문체 교정에 필요하지 않은 단위 확인으로 작업을 중단하지 않음. 수치·부등 관계 유지. |

검사기 실행 환경이 없으면 미실행 사실을 밝히고 직접 검토합니다. 미실행을 후보 0건으로 보고하지 않습니다. 이 표는 기대 행동이며 모델별 통과율을 의미하지 않습니다. 실제 검토 결과와 채택하지 않은 제안은 [전체 점검 기록](../docs/full-review-1.1.0.md)에 있습니다.
