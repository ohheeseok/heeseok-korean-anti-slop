# 강의·실습 자료의 문체 검토

초보자용 자료는 어려운 한자어나 번역투가 없어도 ‘손·자리·층’ 같은 쉬운 비유와 반전형 문장을 반복할 수 있습니다. 문장 하나의 자연스러움과, 여러 장에서 그 표현이 실제 설명을 대신하는지를 함께 봅니다. 구어체·친절한 질문 자체를 슬롭으로 판정하지 않습니다.

## 먼저 구분할 것

- **설명과 조작 지시:** 실제 대상과 행동을 알 수 있는지 검토합니다.
- **시연용 인용:** 말풍선 속 챗봇 응답과 예시 프롬프트는 본문의 집필 말투와 구분합니다. 인용부호가 없어도 화자 라벨·예시라는 역할을 확인합니다. 같은 입력의 전후 비교라면 반복된 문장을 그대로 보존합니다.
- **기획·검토 문서:** ‘이 문장이 첫 단추다’ 같은 내부 수사가 화면에 그대로 나왔다고 보고하지 않습니다. 기획 의도를 이해하는 자료로만 사용합니다.
- **앞선 차시와 화면:** 해당 폴더만 보고 전체 강의에서 용어가 정의되지 않았다고 단정하지 않습니다. 앞 장에서 이미 대응 관계를 알려 주었어도 실제 행동 지시에는 원문에 있는 기능명·대상명을 병기할 수 있습니다.

## L1-11. 지시어로 조작 대상을 대신하는 문구

‘얘’, ‘그 자리’, ‘여기까지’가 누구·어느 기능·어떤 범위를 가리키는지 확인합니다. 자료에 실제 이름이 있으면 그 이름으로 명시하고, 없으면 확인할 항목으로 남깁니다.

- 검토 예: `챗봇은 알려만 주고, 얘는 해준다`, `같은 앱 안에 다른 자리가 있습니다`.
- 교정 방향: 지시어를 자료에 표시된 도구·화면·기능 이름으로 바꾸거나 병기합니다. 자료에 없는 버튼명·이동 경로·설치 절차를 보충하지 않습니다.
- 보존 예외: 화면의 폴더를 가리키는 `여기를 선택하세요`, 바로 앞에서 대상을 명시한 자연스러운 지시어, 강사가 실제로 가리키며 하는 말은 문맥에 따라 유지합니다. 지시어를 모두 딱딱한 명사로 바꾸지 않습니다.

## L2-8. 기능·조작 설명을 대신하는 신체·공간 은유

| 검토 표현 | 확인할 대상과 교정 방향 |
|---|---|
| 손이 없어서 못 한다 / 눈을 달아 준다 | 실행 기능·접근 대상·입력 범위 중 무엇을 뜻하는지 확인하고 해당 조건을 직접 설명. 원인이나 권한 상태를 추측하지 않음 |
| 자리 옮기기 / 다른 자리 | 실제 화면·기능·도구 전환을 뜻하면 그 이름을 사용. 물리적 좌석 이동이면 유지 |
| 1층에서 부탁 / 3층으로 옮겨 폴더 지정 | 강의에서 정한 비유인지 확인. 정의된 별칭이라도 단계별 지시는 실제 기능명과 연결. 물리적 층수나 전문적인 계층 구조는 유지 |
| 사고 반경 / 좁은 폴더 | 어떤 파일·폴더까지 작업 대상인지 확인. 앞뒤에 실습용 복사본 폴더가 지정돼 있으면 ‘작업 대상 폴더’ 등으로 명시 |

‘층’, ‘자리’, ‘손’이라는 단어만으로 판정하지 않습니다. 정의된 계층 모델이나 보안 분야의 정식 용어도 해당 독자·문맥에서 적절하면 유지합니다. 작성자가 은유를 피하도록 요청했더라도 실제 사물과 전문 용어를 다른 뜻으로 바꾸지 않습니다.

### 반전형 문장과 실제 대조

`몰라서 못 한 게 아닙니다. 손이 없어서 못 한 겁니다.`처럼 반전 뒤의 비유로 설명을 끝내면 그 비유가 대신한 기능·조건을 확인합니다. `바뀐 건 자리입니다`처럼 여러 변경 조건을 한 단어로 정리하는 결말도 확인합니다.

대조 자체를 지우지 않습니다. 안내만 제공된 상황과 파일이 실제로 바뀐 상황의 차이는 정보입니다. 다만 한 시연의 차이를 모든 챗봇·모든 환경의 능력 차이로 확대하지 않습니다. 표현을 풀다가 원문에 없던 ‘실행 권한이 없었다’, ‘폴더를 보면 OS도 알게 된다’ 같은 설명을 만들지 않습니다. 근거가 필요한 원인 단정은 본문 밖의 확인 항목으로 남깁니다.

## L3-7. 교훈형 판정을 실제 절차·완료 조건으로 설명

`사고가 나도 되는 상태`, `되돌릴 수 있으면 성공`, `아직 성공이 아니다`는 쉬운 말이지만 조치·조건을 교훈처럼 압축할 수 있습니다. 주변에 실제 절차가 있으면 그 내용을 중심으로 설명합니다.

| 원문과 문맥 | 교정 방향 예시 | 보존할 정보 |
|---|---|---|
| 사고가 나도 되는 상태를 만듭니다. 뒤에 복사본·변경 전 목록 준비가 제시됨 | 실습용 복사본과 변경 전 목록을 준비합니다. | 나머지 작업 범위·중단 절차도 본문에 남김. ‘사고가 허용된다’는 식으로 의미 확대 금지 |
| 좁은 폴더만 지정합니다. 앞뒤에서 실습용 복사본 폴더를 지정함 | 실습용 복사본 폴더만 지정합니다. | `만`이라는 범위 제한. 임의로 파일 수·용량 제한을 추가하지 않음 |
| 되돌려 보지 않았다면 아직 성공이 아닙니다. 실습 완료 기준으로 제시됨 | 되돌리기를 확인하기 전에는 실습이 완료되지 않습니다. | 확인이라는 행위, 그 전에는 미완료라는 조건. 권고로 약화하지 않음 |

‘성공’이라는 말이나 단정형 어미 자체가 잘못은 아닙니다. 실제 완료 기준이면 유지할 수도 있습니다. 문장이 길어져도 조건이 불분명해지면 개선이 아닙니다. 반대로 `복사본으로 작업합니다`, `선택된 폴더 이름을 다시 봅니다`, `화면이 다르면 멈춥니다`처럼 대상·행동·조건이 분명한 문장은 유지합니다.

## 강의 어조와 사실 보존

- `~해보겠습니다`, `~보세요`, `이런 폴더, 있으시죠`를 일괄적으로 명사형·합니다체로 바꾸지 않습니다. 학생에게 요구하는 행동과 강사의 시연 예고도 구분합니다.
- 실습 단계, 이름·날짜 예시, 파일 확장자, 전후 비교의 입력 동일성을 보존합니다. 반복을 줄이려고 시연 프롬프트를 다르게 고치지 않습니다.
- 기능 범위·지원 환경·구독·요금 주장은 문체 규칙만으로 고치거나 검증하지 않습니다. 원문 근거와 지칭 대상이 불분명한 경우에만 확인 사항을 적습니다.
- 수정안은 새 기술 설명을 집필하는 일이 아닙니다. 원문에 기능의 실제 이름이 없으면 중립적인 절차명으로 바꾸거나 확인합니다.

검사기는 일부 신체·앱·층 비유 후보만 찾습니다. 지시 대상, 인용 경계, 여러 장에 걸친 대조와 시연 조건은 직접 읽어 판단해야 합니다. 탐지 수가 적거나 0이어도 문체가 적절하다는 뜻은 아닙니다.
