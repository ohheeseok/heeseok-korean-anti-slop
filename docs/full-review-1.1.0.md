# 전체 스킬 점검 — 1.1.0

2026-10-24에 1.0.8을 기준으로 SKILL.md, 모든 참고 문서, README, 변경 기록, 사례 기록, 검사기와 테스트를 점검했습니다. 사용자 제공 강의·기술 해설 원본은 수정하지 않았습니다. 기존 사례 기록은 작성 당시의 결과로 남기고 현재의 편집 기준과 구분했습니다.

## 검사기에서 재현하고 고친 문제

처음 점검에서 아래 여섯 동작을 1.0.8 코드로 재현했습니다.

- `--rules L2`를 사용해도 L3-1 연속 검사 결과가 출력됨
- 대문자 STYLE 태그의 텍스트가 기본 본문 검사에 섞임
- 작은따옴표 HTML 속성 누락
- 속성 순서가 바뀐 meta description 누락
- 큰따옴표 JS 안내 문자열 누락
- `--skip-quoted`가 여러 줄 코드 펜스의 내부 예시를 남김

정적 HTML 파서로 본문·메타 텍스트를 구분하고 title·desc 중복, 속성 순서·따옴표, 일부 JS 문자열 수집을 보완했습니다. JSON 데이터 스크립트와 JS 주석은 안내 문자열로 세지 않습니다.

수정 후 재검토에서 세 가지 경계 사례도 확인해 고쳤습니다.

- 규칙 번호의 단순 접두어 비교: `L1-1`이 `L1-12`까지 선택함. 레이어·정확한 ID와 문자 접미사 하위 ID를 구분하도록 변경
- 행 첫머리의 한 줄 삼중 백틱을 열린 코드 펜스로 오인해 이후 본문을 제외함. 펜스와 인라인 코드를 구분하고 이중 백틱도 처리
- 짧거나 한글이 없는 문장을 먼저 제외해, 실제로 떨어져 있는 선언문을 연속으로 셈. 연속 판정 전에 문장을 임의로 삭제하지 않도록 변경

빈 규칙 선택 항목, 미구현 ID, 음수 예시 수는 종료 코드 2로 알립니다. 종결어미 분포는 문장·행을 나눈 참고 정보이며 완전한 한국어 문장 분석이 아닙니다.

## 두 모델의 독립 검토와 반영 판단

Claude에는 의미 보존과 실제 교정 행동을, Gemini에는 검사기와 README의 동작 일치를 검토하게 했습니다. 각 모델은 제공한 지침·코드를 읽고 답했으며 자체 도구 실행은 하지 않았습니다. 코드 결함은 주 작업에서 직접 재현하고 테스트로 확인했습니다. 수정 전 검토와 수정 후 재검토를 각각 진행했습니다.

Claude의 첫 검토에서는 문맥이 적은 입력에 보류가 많았고 교정과 무관한 단위 질문도 나왔습니다. 상위 지침에 안전한 부분의 실제 교정과 질문 범위를 명시한 뒤, 문맥을 추가한 새 입력 7개로 재검토했습니다. 중복 경구·명료함 예고·이미 설명한 신체 비유를 줄이고, 실제 세 단계·복사본 작업 지시·완료 조건·의무·수치를 보존하는 결과를 확인했습니다.

다만 7개를 모두 의미 보존 성공으로 계산하지 않았습니다. 두 결과에는 다음 추정이 섞였습니다.

- 대사와 침묵 조정이 여운 증가를 위한 수단이라고 인접 문장만으로 연결
- 브랜드 방향성과 고객 반응 전체를 광고의 약속과 후기의 경험으로 축소

이 제안은 교정 정답으로 채택하지 않았고, 관계·범위의 임의 보충을 막는 지침과 행동 점검 사례로 반영했습니다. ‘좁힌다’를 ‘정리한다’로 바꿔 범위 축소가 사라지는 예, ‘가로질러’를 ‘전체’로 바꿔 범위가 커지는 예도 수정했습니다. ‘비용을 센다’의 교정은 계산·집계·포함 범위 중 실제 뜻에 따르도록 조건을 명시했습니다.

Gemini가 지적한 규칙 번호 충돌·인라인 백틱·짧은 문장 문제는 직접 확인 후 수정했습니다. 기존의 접두어 선택 자체는 문서에 적혀 있던 동작이므로 모든 선택 확장을 기존 계약 위반으로 보지는 않았습니다. 1.1.0에서 규칙 ID의 선택 방식을 더 명확히 바꿨습니다. `L3-1`이 `L3-1a`도 포함하는 동작은 유지하고 문서에 명시했습니다.

## 검증 결과

- CLI 회귀 검사 **25개 통과**: 사용자 예시, 문자 그대로의 표현, 규칙 선택, 잘못된 옵션, HTML 본문·숨은 텍스트, 인라인 태그·엔터티, 인용 제외, 짧은 문장·연속 판정, 여러 파일 출력 순서, 입력 바이트·수정 시각 불변성, 예시 수 제한
- SKILL.md frontmatter 검증과 저장소 내부 Markdown 링크 확인
- Git 공백 오류 검사

재현 명령은 저장소 루트에서 `python -m unittest discover -s tests -v`입니다. 테스트는 검사기의 동작을 확인합니다. 문장 교정의 의미 보존 전체를 자동 검증하거나 일반 문서의 탐지율을 측정한 결과가 아닙니다.

## 남은 한계

검사기는 일부 표면 패턴만 찾습니다. 지시 대상, 기술적 의미, 문단의 논리, 실제 세 단계 여부, 논문의 보장 범위는 문맥 검토가 필요합니다. 정적 HTML 추출은 CSS 표시 상태·실행 후 DOM·전체 JavaScript 문법을 해석하지 않습니다. 여러 줄 인용 경계도 완전히 파악하지 못합니다.

원문이 없는 과거 사례의 사실 전체, 외부 저장소의 최신 변경, 원 논문의 기술적 주장 전체를 이번 점검에서 검증한 것은 아닙니다. 두 모델의 의견도 원문 대조와 재현 결과를 근거로 선별했습니다. 후보 수나 모델 간 동의 수를 품질 점수로 사용하지 않습니다.
