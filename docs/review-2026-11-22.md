# 메타카피·규정·면책투·과잉 정당화 검토 — 1.3.0

2026-11-22에 사용자가 세 문체(메타카피, 컴플라이언스 문체, 자기합리화적 화법)의 정의·예시·교정 방법을 물었습니다. Claude·Codex·Gemini가 같은 질문에 독립적으로 답한 뒤 서로의 답을 검토했고, 그 결과와 사용자가 제공한 비교 글을 스킬에 반영했습니다. 아래 예시는 모두 합성 사례이며 실제 사용자 문서가 아닙니다.

## 진행

| 단계 | 내용 |

| 외부 글 검토 | 사용자가 제공한 비교 글의 인용 문헌을 확인하고, 반영할 부분과 반영하지 않을 부분을 구분 |

## 합의한 결정

| 쟁점 | 결정 | 근거 |
|---|---|---|
| 메타카피 범위 | 글·절·슬라이드에 대한 예고와 글의 전달 방식 자평. 로드맵·범위 한정·실제 진행 안내는 유지 | 세 모델 합의. 예고를 더 짧은 예고로 바꾼 1차 교정은 불완전하다고 판정 |
| 컴플라이언스 문체 | ‘규정·면책투’로 부르고 규정체 과잉(L3-8)과 근거 없는 면책·헤지(L3-9)로 분리 | 관용구는 풀면 되지만 헤지는 지우면 주장이 강해져 교정 절차가 반대 |
| 자기합리화적 화법 | ‘과잉 정당화’(L3-10)로 개명 | 원래 이름은 작성자의 동기를 판정함. 스킬은 의도를 판정하지 않음 |
| 품질 자평 | 글의 전달 방식(`체계적으로 정리했습니다`)은 L1-16, 작업 품질(`꼼꼼히 검토했습니다`)은 L3-10 | Codex는 둘 다 메타카피, Gemini는 작업 품질을 의사 엄밀성으로 판정. 평가 대상(글/작업)을 기준으로 나눔 |
| 반영 위치 | 새 레이어 없이 L1·L3에 규칙 ID 추가 | 1차에 Claude가 L4를 제안했으나 기존 규칙과 경계가 겹친다는 두 모델 의견 수용 |

## 모델이 서로 지적한 교정문 오류

| 출처 | 오류 | 처리 |
|---|---|---|
| Claude 1차 | `켜 두는 것이 좋습니다` → `켜 두세요`(권고→지시) | 반영하지 않음 |
| Claude 1차 | `데이터를 변경할 수 있으므로` → `파일을 덮어씁니다`(가능성→단정, 동작 창작) | 문맥에 동작이 있을 때만 쓰고 가능성은 유지하는 사례로 재작성(대조 사례 14) |
| Claude 1차 | 근거 없는 설계 설명을 `합치겠습니다`로 바꿈(작성자 입장 변경) | 평가 수식만 걷어내고 이유는 유지 + 확인 사항(대조 사례 15) |
| Gemini 1차 | `지양되어야` → `해서는 안 됩니다`, `강력히 권장` → `권합니다`, `권장드립니다` → `좋습니다` | 강도 보존 규칙으로 반영(L3-8, 어미 가이드) |
| Gemini 1차 | 예고를 `이 절에서는 ~을 정리합니다`로 줄이고 끝냄 | 불완전한 교정의 예로 반영(L1-16) |
| Codex 1차 | `오히려`·`불가피하게`·`의도적으로` 부사만 찾는 정규식 | 정상 문장을 대량으로 잡아 채택하지 않음 |

## 사용자 제공 비교 글에서 반영한 것과 반영하지 않은 것

반영: 메타담화 연구를 정상 용법과 과잉의 경계로 사용, 가상 반론과 자가 승인 유형, 과잉 주장과 면책의 짝, 행위자 은폐와 L1 피동 규칙의 연결, 교정 전 예문 일부.

반영하지 않음: 교정 후 예문(원문에 없는 수치·환경·계획을 넣음. 실패 점검 사례로만 반영), 숨은 목적을 판정하는 비교 표, 메타 예고 전면 삭제·확인된 사실 단정·해결 계획 서술 같은 과잉 교정 원칙, 광고 카피·SEO 용어, 확인할 수 없었던 칼럼 인용. 인용 논문 두 편은 초록 범위로 설명을 좁혔습니다([근거 자료](../references/sources.md)).

## 변경안 검토에서 수용한 지적

| 검토자·대상 | 지적 | 처리 |
|---|---|---|
| Gemini·문서 | 표본 예시가 문맥에 없는 외적 타당도 한계를 추론해 넣음 | 한계 절에 같은 내용이 있는 문맥으로 바꾸고 가능성·신중 의무 유지 |
| Gemini·문서 | 옵션 예시의 시제 변경(`둔 것은 → 둡니다`), 가상 반론 예시의 `느리지만` 단정 | 과거형 유지, 표에 있는 값만 사용 |
| Gemini·문서 | `확장성을 고려해 의도적으로 분리`만 원문 유지하고 같은 구조의 다른 문장은 교정해 판정이 엇갈림 | 평가 수식만 걷어내고 원문의 이유는 유지 + 확인 사항으로 통일 |
| Gemini·문서 | 조건이 없으면 원문 유지라는 설명과 헤지를 다듬은 예시가 충돌 | 조건이 없으면 헤지를 지우거나 구체화하지 않고 같은 강도로 표현만 다듬는다고 정리 |
| Gemini·문서 | 인용 논문 설명이 초록 범위를 넘음 | 연쇄 추론·편향 단서 등 범위를 밝히고 ‘증거’를 ‘보고’로 낮춤 |
| Codex·문서 | 과잉 주장과 면책을 근거 수준의 주장 하나로 합치는 규칙이 SKILL 2절(문체 판단만으로 주장을 약화하지 않음)과 충돌 | 합치지 않고 어긋나는 범위를 확인 사항으로 기록하도록 수정 |
| Codex·문서 | 스크립트 예시가 확인된 동작 하나로 원문의 넓은 변경 범위를 좁힘 | 원문 범위를 유지하고 확인된 동작을 덧붙이는 예시로 수정 |
| Codex·문서 | 설명문 자체의 가짜 대조(`교정의 중심은 삭제가 아니라 조건 확인`)와 확인되지 않은 빈도 평가 | 삭제·재작성 |
| Codex·문서 | 한 곳만 가리키는 위치 안내, 실제 요약을 담은 `핵심 요약` 제목도 보존 대상 | L1-16 보존 기준에 추가 |
| Gemini·검사기 | `정리한 명세서`(관형형), `결함이 아니라 라벨링 오류`(원인 분석), `합리적 선택 이론`, `주입한 뒤에 설계`, `허용 범위`, `신중한 검토 부탁드립니다`, `의료 전문가와 상의해야 한다`, `IRB 관련 절차에 따라` 오탐 | 서술형만 잡기, `아니라` 뒤 정당화 어휘 요구, 용어·복합명사 제외, 권고 상투구로 한정, `관련 절차에 따라` 규칙 제거 |
| Gemini·검사기 | `살펴봤습니다`·`한해`·`권장 드립니다`·`아닌/아닐`·`보안전문가`·`의도된 설계`·`꼼꼼하게` 미탐, 소수점(`v2.1`)에서 문장이 끊김 | 활용형·띄어쓰기·복합어를 반영하고 소수점은 문장 안 문자로 처리 |
| Gemini·검사기 | 부정 테스트 다수가 규칙 핵심 어휘를 포함하지 않아 검증력이 약함 | 핵심 어휘를 포함한 오탐 문장을 부정 테스트에 추가 |

수용하지 않은 지적:

- 옵션·동기화 예시의 `기능 부족이 아니라`, `기술적 타협이 아니라`를 남기자는 Codex 의견: 아무도 하지 않은 지적을 세워 부정하는 수사가 과잉 정당화의 핵심이므로 걷어내되, 실제 질문·리뷰 의견에 답하는 부정은 남긴다는 조건과 문맥 표시를 추가했습니다.
- `관련 백업 절차`를 그대로 두자는 두 모델의 의견: `관련 ~ 절차`가 L3-8의 교정 대상 관용구라서 `백업 절차`만 남겼습니다.
- `이 항목은 ~ 다룹니다`, `공유하는 일은 삼가야` 등을 번역투로 본 Gemini 의견: 기존 문서와 같은 자연스러운 구문이라 유지했습니다.
- `강력히 권장됩니다`를 검사기에서 빼자는 Gemini 의견: 보안 공지 같은 정상 용례가 있지만 후보로 검토할 가치가 있어 유지했습니다.

검사기 확인 범위: 위 지적의 오탐·미탐 문장을 포함해 양성 44개·음성 37개 문장으로 확인했습니다. 이 저장소의 검토 기록과 1.2.0 평가 출력(한국어 약 1만 2천 자)에서는 새 규칙 후보가 나오지 않았습니다.
