# 1.2.0 교정 동작 점검

검토일: 2026-10-25. 기존 1.1.0과 1.2.0 초안으로 같은 입력 20개를 각각 한 번 교정했습니다. Claude에 예상 교정문·보존 체크·다른 버전의 출력은 주지 않았습니다. Gemini에는 사례마다 A/B 순서를 섞은 원문과 실제 결과를 주고 버전명을 숨겼습니다. Codex가 실제 원문과 결과를 다시 대조해 이견을 기록했습니다. 사람 검수나 일반 성능 측정은 아닙니다.

입력은 새 합성 문서 발췌 18개와 기존 공개 사례의 재구성 2개입니다. 교육용 가상 상황 재작성이나 사용자가 수락한 문단 쌍을 정답으로 쓰지 않았습니다. 출처와 판단 기준은 [cases.jsonl](../../cases.jsonl), 절차는 [평가 안내](../../README.md)에 있습니다.

## 최초 실행에서 확인한 점

두 버전 모두 실제 장치·좌석·농도·좌표계·세 단계·금지 지시·진행 상태·근접 비교·시험 범위를 다룬 보존 사례 10개를 그대로 남겼습니다. 비유의 대상이 정의된 경우, 중복 경구, 정보 없는 예고, 이중 피동, 반복되는 병목 진단도 양쪽에서 실제로 줄였습니다. 이 입력들에서 보강 전 버전도 잘 작동했으므로 성능이 전반적으로 좋아졌다고 주장하지 않습니다.

| 확인 항목 | 관찰 | 처리 |
|---|---|---|
| T07 비용 정의와 표의 관계 | 두 최초 출력 모두 추가 통신요금은 남겼지만 원문의 ‘이 표’는 생략했습니다. | 정의를 다른 문장에 합쳐도 대상·위치를 남기도록 좁게 보완했습니다. |
| T11 두 항목의 필수성 | 초안 출력은 ‘모두’를 생략했습니다. Gemini는 의미 변경, Codex는 ‘A와 B’도 두 항목을 요구하므로 판단 보류로 보았습니다. | 판정 이견을 남겼습니다. 보완에서는 범위·정도 표현의 기능을 다시 확인하고 모두를 유지했습니다. |
| T09 의미가 불명확한 구간 | 양쪽 모두 첫 문장을 고치고 둘째 문장은 뜻을 추측하지 않은 채 확인 메모를 본문 밖에 뒀습니다. | 필요한 부분만 보류하는 동작을 확인했습니다. |
| T17·T18 문서 전체의 반복 | 제약을 이미 설명한 반복 진단은 줄이고, 실제 측정·조건·결론 재확인은 유지했습니다. | 진단 횟수만으로 삭제하지 않는 동작을 확인했습니다. |

## 보완 뒤 재실행

최초 출력과 판정은 수정하지 않았습니다. 정의문과 편집 메모의 구분, 실제 범위를 전달하는 표현의 보존을 지침과 대조 사례에 보완한 뒤 T07·T11만 별도 실행했습니다. Gemini의 재검토도 기존 판정·버전명 없이 진행했습니다.

| 사례 | 보완 뒤 실제 출력 | 독립 재검토 |
|---|---|---|
| T07 | 전송을 잘못 중단한 뒤 다시 전송하느라 추가로 쓴 통신요금을 이 표에 비용으로 기록한다. | 의미 유지 · 문체 개선 · 과교정 없음 |
| T11 | 지침에 대상 파일과 적용 기간을 모두 적습니다. | 의미 판단 보류 · 문체 개선 · 과교정 판단 보류 |

T07에서는 위치가 보존됐다는 재검토 결과를 얻었습니다. T11에서는 두 항목을 모두 적는다는 조건은 남았으나, 다른 절에서 정의를 참조하는지 알 수 없어 Gemini가 의미 보존을 판단 보류했습니다. 이는 모두를 보존하는 문제와 별개인 문맥 범위의 문제입니다.

### 문맥을 명시한 별도 대조 T21

T11의 첫 정의문이 독자용 본문이며 다른 절에서도 참조된다는 context를 명시한 T21을 별도로 만들었습니다. 원래 T11 입력이나 최초 출력을 바꾸지 않았으며, 새로운 비공개 평가 입력인 것처럼 세지 않았습니다.

> 이 문서에서 맥락의 밀도는 지침에 대상 파일과 적용 기간을 모두 적는 것을 뜻합니다. 지침에 대상 파일과 적용 기간을 적습니다.

독립 재검토: 의미 유지 · 문체 개선 · 과교정 없음. 정의를 남기는지 확인하는 별도 문맥 사례이며 T11의 보류 판정을 소급해서 없애지 않았습니다.

최종 보완판으로 20개를 모두 다시 실행한 결과는 아닙니다. 보완 뒤 결과를 최초 실행의 실패·이견에 덮어쓰거나 20개 전체의 무실패 결과로 합산하지 않았습니다.

## 공개 기록

- [실제 출력 43개](outputs.jsonl): 최초 두 실행 40개, 보완 뒤 2개, 문맥 명시 1개를 phase로 구분
- [Gemini 판정](reviewer-judgments.jsonl): 초기 A/B 구분과 재검토 원문 보존
- [Codex 대조·이견](adjudication.jsonl): T11의 판단 차이를 포함
- [실행 범위와 공통 안내](run-info.json): 입력 종류, 기준 커밋, 검사기 미실행 안내

스킬을 사용한 편집에서는 도구 실행을 막아 검사기를 실행하지 않았습니다. 별도로 기존 CLI 회귀 검사 25개를 실행해 통과했고, 스킬 형식·내부 링크·평가 파일의 구조도 확인했습니다. 후보 수·글자 수·자동 등급을 교정 품질 점수로 사용하지 않았습니다.

## 이후 평가에서 보완할 점

짧은 발췌와 소수 절의 비교가 중심입니다. 실제 긴 문서 전체, 사용자가 특정 문단을 수락한 교정 쌍, 여러 번의 독립 실행과 사람 검토는 더 확보해야 합니다. 공개한 사례를 반복 실행한 결과는 새로운 비공개 평가셋의 성능으로 보고하지 않습니다.
