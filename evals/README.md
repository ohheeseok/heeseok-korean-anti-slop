# 실제 교정 결과를 평가하는 방법

문체가 달라졌다는 사실과 뜻을 보존했다는 판단을 분리합니다. 검사기 후보 수나 글자 수 감소를 품질 점수로 쓰지 않습니다.

## 자료와 출처

`cases.jsonl`은 원문·문맥·보존할 정보·검토할 문체를 담은 공개 점검 사례입니다. 각 레코드에 출처 종류를 기록합니다.

| source_kind | 뜻 |
|---|---|
| synthetic_holdout | 이번 비교 실행용으로 새로 만든 입력. 작성 에이전트에게 보존 체크나 기대 결과를 제공하지 않음 |
| adapted_public_case | 기존 공개 사례 기록에서 발췌하거나 문맥을 붙여 재구성한 입력. source_url로 범위를 확인할 수 있음 |
| synthetic_clarification | 해석이 갈린 기존 입력에 문맥을 명시한 별도 대조 사례. parent_case_id를 기록하며 최초 평가와 같은 입력으로 세지 않음 |
| accepted_edit_pair | 사용자가 특정 교정문을 명시적으로 수락한 실제 문단 쌍. 수락 근거와 공개 가능한 출처가 있을 때만 추가 |

현재 파일에는 사용자가 수락한 실제 문단 쌍이 없습니다. 합성 사례나 이전에 스킬 지침으로 쓴 문구를 그 종류로 승격하지 않습니다. 공개된 점검 자료는 이후 실행에서 독립적인 비공개 평가셋이 아니므로, 같은 자료의 반복 결과를 일반화 성능으로 보고하지 않습니다.

원문이 아닌 것으로 오해할 수 있는 설명용 가상 상황은 `context`나 입력에 명시합니다. AX 웹 예제처럼 원문에 없는 상황을 붙여 새로 쓴 교육용 재작성은 의미 보존 교정의 정답이나 실제 사용자 수락 자료로 쓰지 않습니다.

`context`는 작성 상황·독자·지칭 대상에 관한 정보이며 독자용 `input`과 구분합니다. 정의문이 실제 본문인지 모호한 점이 평가에 영향을 주면 최초 기록을 남기고 문맥을 명시한 별도 사례로 확인합니다. 뒤늦게 명시한 문맥으로 최초 출력을 소급해서 합격·실패 처리하지 않습니다.

## 실행

1. **자료 준비:** 실제 요청과 원문을 작성 에이전트에게 제공합니다. `check`와 예상 교정문·이전 판정은 제공하지 않습니다. 각 사례의 문맥은 그 사례 안에서만 사용합니다.
2. **출력 보존:** 실제 교정문과 본문 밖 확인 메모를 기록합니다. 검사기를 실행하지 않았으면 그 사실을 남깁니다. 출력이 마음에 들지 않는다는 이유로 원래 실행 기록을 수정하지 않습니다.
3. **원문 대조:** 아래 기준으로 각 출력을 검토합니다. 가능하면 작성에 관여하지 않은 검토자에게 입력과 순서를 섞은 결과를 주고, 어느 버전의 출력인지 숨깁니다.
4. **실패 반영:** 특정 수치·서법·관계가 바뀐 사례를 근거로 좁게 수정합니다. 재검토가 필요하면 영향을 받은 사례를 새 실행으로 남깁니다. 최초 출력과 재실행 결과를 섞어 한 번에 통과한 것처럼 보고하지 않습니다.

같은 버전을 여러 번 실행해도 결과가 달라질 수 있습니다. 한 번씩 실행한 버전 비교는 해당 실행의 관찰이며 개선 원인의 통계적 증명이 아닙니다.

## 판정 기준

| 항목 | 확인할 내용 | 기록 |
|---|---|---|
| 의미·정보 보존 | 수치·단위·이름·범위·부정·조건·순서·인과·의무·추정·평가 강도가 유지됐는가? 정보가 추가·누락됐다면 해당 구간은 어디인가? | 유지 / 변경 / 판단 보류 + 근거 구간 |
| 문체 개선 | 실제로 문제였던 번역투·은유·경구·호응·불필요한 압축·반복이 줄었는가? 다른 추상어나 형식만 바꾼 것은 아닌가? | 개선 / 불충분 / 원래 문제 없음 + 근거 |
| 과교정 | 실제 사물·기술 용어·비교·세 단계·완료 조건·자연스러운 원문을 불필요하게 바꿨는가? | 없음 / 있음 / 판단 보류 + 근거 |
| 확인 메모 | 필요한 의미만 묻는가? 확인할 필요 없는 단위·실험 설계를 요구하거나 메모를 본문에 섞지 않았는가? | 적절 / 부적절 / 해당 없음 |

특정 문구와 일치하는지를 정답 기준으로 쓰지 않습니다. 의미가 바뀐 출력은 문체가 좋아졌어도 성공 사례로 세지 않습니다. 판정이 갈리면 근거와 이견을 남기고 좋은 점수 하나로 합치지 않습니다.

## 이후 실제 문단 쌍을 추가할 때

원문과 교정문, 사용자가 수락한 범위·근거를 함께 기록합니다. 민감한 이름·소속·내부 작업 지시는 공개 자료로 복사하지 않습니다. 익명화하면서 문장·맥락을 바꿨다면 실제 원문 그대로의 쌍이 아니라 익명화·재구성 자료라는 사실을 표시합니다. 수치·서법 보존과 문체 선호는 따로 검토하고, 좋은 사례뿐 아니라 실패와 이견도 남깁니다.
